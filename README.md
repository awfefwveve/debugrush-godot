# 청강 디버그 러시

기획서의 **재료 획득 → 두 재료 조합 → 단말기 수리**를 중심으로 만든 Godot 4 / GDScript 게임입니다. 현재는 **챕터 1의 10개 스테이지 + 기획자용 스테이지 제작기**를 제공합니다. 챕터 2·3은 기존 저장 데이터가 있어도 잠겨 있습니다.

## 바로 실행

Godot이 없는 사람에게 보낼 때는 **DebugRush-Designer-Windows.zip**을 보내면 됩니다. 압축을 풀고 **DebugRush.exe**를 실행하는 Windows 64비트 배포판이며, 폰트와 게임 데이터가 실행 파일에 포함되어 있습니다. 메인의 **스테이지 제작기**에서 편집 도구를 엽니다. 아래는 소스 프로젝트를 실행하는 방법입니다.

1. Godot 4에서 이 폴더의 `project.godot`를 가져옵니다.
2. **F5**를 눌러 실행합니다.
3. **프로젝트 시작 → 1-01 시작 → 디버깅 시작**을 선택합니다.

Windows에서는 `PLAY.cmd`를 더블클릭해도 됩니다. 현재 PC의 바탕화면 Godot 4.7.2 설치 경로를 감지합니다. 다른 PC에서는 Godot 실행 파일을 `PLAY.cmd` 위로 끌어 놓거나, Godot에서 프로젝트를 직접 여세요.

검증 버전: **Godot 4.7.2 stable / Windows / OpenGL Compatibility**. GDScript만 사용하며 C#, Python, 플러그인은 실행에 필요하지 않습니다. ZIP을 받은 경우 먼저 전체 압축을 풀어 주세요.

## 조작

| 키 | 기능 |
| --- | --- |
| WASD / 방향키 | 이동 |
| E / Enter | 가까운 재료함에서 획득, 제작대에 투입·완성품 받기, 단말기에 전달 |
| Space | 점프 · 분홍색 다이아몬드 탄환 패링 |
| Shift | 짧은 무적 대시, 재사용 대기 1.35초 |
| Q | 마지막 소지품 삭제. 빈손으로 제작대 옆에서 사용하면 제작대를 비움 |
| Tab | 조합표와 조작법, 확인 중 시간 정지 |
| Esc | 일시정지 |

**붉은 탄환은 점프해도 피해를 줍니다.** 이동과 대시로 피하세요. 분홍 탄환을 점프로 패링하면 해당 적이 3.3초간 멈추고 2초의 시간을 회복합니다. 단말기 패치가 완료되면 탄막이 사라지고 모든 적이 잠깐 멈춥니다.

## 첫 스테이지

1. 왼쪽 위 **기획** 재료함 가까이에서 E를 누릅니다.
2. 왼쪽 **A 단말기** 가까이에서 E로 기획 재료를 전달합니다.
3. **기획 1개 + 프로그래밍 1개**를 모읍니다. 프로그래밍은 오른쪽 아래에 있습니다.
4. 가운데 제작대 근처에서 E로 두 재료를 넣습니다.
5. 제작 완료 아이콘이 뜨면 E로 **시스템 기획서**를 받습니다.
6. 오른쪽 **B 단말기**에 E로 전달하면 클리어됩니다.

재료함은 무제한입니다. 재료와 완성품을 합쳐 두 개까지 들 수 있습니다. 잘못 조합했거나 동선이 꼬였으면 Q로 비우고 다시 모으세요. 단말기가 두 개의 물품을 요구하면 하나씩 나누어 전달해도 됩니다.

## 들어 있는 콘텐츠

- 챕터 1 캠페인 10개 스테이지. 챕터 2·3 데이터는 보관하지만 진입과 해금은 차단합니다.
- 드래그 배치, 16px 스냅, 개별 속성 편집, 60단계 취소·복구, JSON 저장·불러오기.
- 시드 기반 자동 생성, 필수 모듈·배치·이동 동선 검사, 캠페인 기록과 분리된 테스트 플레이.
- SVG 벡터 50개 슬롯을 EXE 옆 `art/`에서 읽는 아트 교체 기능.
- 스테이지마다 시작 이야기, 수리 요구, 난이도 변화, 결과와 클리어 기록.
- 적의 공격 예고, 조준 부채꼴과 방사형 탄막, 점프 패링, 대시, 피격 무적.
- 2칸 소지품, 제작 대기, 순차 투입, 1~2개 물품 요청, 단말기별 다단계 복구.
- 남은 시간·HP 보너스, 연속 수리 점수, 별 3개 기록, 업적 8개.
- 단계 잠금 해제, 진행·설정 자동 저장, 재도전, 일시정지, 조합표.
- 사운드·음악 설정, 흔들림 감소, 탄속과 시간 소모를 낮추는 연습 보조.
- 코드로 그린 SD 캐릭터·적·UI, 복구 효과·파티클, 코드로 합성한 음악과 효과음.

스테이지는 872×500px 아레나를 사용합니다. 제작기는 배경 모듈 12종·자동 연결 벽·재료함·제작대·시작점·단말기·버그·벽을 배치하고 단말기 요청과 버그 탄막을 설정합니다. 예제 JSON은 `samples/`에 있습니다. 제작한 스테이지는 제작기에서 열어 테스트하며, 캠페인에 자동 등록하거나 챕터를 해금하지 않습니다. 자세한 사용법과 아트 규격 HTML·CSV·빈 SVG 템플릿은 기획자용 Windows 배포판에 동봉했습니다.

## 수정할 곳

| 파일 | 역할 |
| --- | --- |
| `scripts/game_data.gd` | 조합, 챕터·스테이지 이름과 이야기, 업적, 제한 시간, 공격 속도와 요구 물품 |
| `scripts/main.gd` | 이동·충돌·전투·제작·전달·저장·화면과 메뉴 |
| `scripts/synth.gd` | 신스 배경음과 효과음 |
| `scripts/stage_editor.gd` | 기획자 편집 UI, 파일 대화상자, 취소·복구, 임시 저장 |
| `scripts/stage_document.gd` | JSON 형식, 검증, 이동 동선 탐색, 시드 기반 생성 |
| `scripts/art_bank.gd` | 외부 SVG 파일명·캔버스·피벗 규격과 로딩 |
| `main.tscn` | 시작 씬 |
| `tests/test_game.gd` | 게임 로직 통합 검사 |

수정할 상수와 스테이지 설정은 `game_data.gd`의 `stage()`에 모여 있습니다. 아레나의 재료함·제작대·단말기 좌표는 `main.gd` 상단에 있습니다.

## 저장 및 검증

게임은 `user://debug_rush_save.json`에 저장합니다. Windows 기본 경로는 `%APPDATA%\Godot\app_userdata\청강 디버그 러시\debug_rush_save.json`입니다. 스테이지 진행, 별·점수·최단 기록, 업적, 설정을 보관합니다. 진행 중인 스테이지의 위치나 제작 상태는 저장하지 않습니다.

통합 검사 실행:

```powershell
godot --headless --path . --script res://tests/test_game.gd
godot --headless --path . --script res://tests/test_editor.gd
```

**검증 결과: 캠페인 212개 + 제작기 106개 검사 통과.** 챕터 잠금, 생성 시드 재현성, 36가지 자동 배치, 잘못된 문서·막힌 동선 거부, 편집 이력, JSON 왕복, 사용자 스테이지 조합·전달·클리어, 캠페인 기록 격리, PNG 크기 검사를 포함합니다. 첫 캠페인 스테이지는 실제 이동 입력으로 완료했습니다. 전체 클리어 로직 검사는 적을 비활성화했으며, 실제 난이도와 재미는 플레이테스트로 조정해야 합니다.

Godot의 실제 OpenGL 렌더러로 시작 화면·스테이지 선택·스토리·게임 화면·조합표·설정·일시정지·결과·업적 화면을 확인했습니다. 이 작업 환경에서 Windows 루트 인증서 저장소 경고가 출력됐으나, 게임은 네트워크를 사용하지 않고 스크립트 오류 없이 실행됐습니다.

## 폰트

Noto Sans KR의 500 웨이트 정적 인스턴스를 포함합니다. Google Fonts 배포본을 사용했으며, 라이선스는 `assets/OFL.txt`에 있습니다. 글꼴 외 외부 게임 아트·음원은 사용하지 않았습니다. 기획서에 실린 다른 게임의 참고 이미지는 게임에 포함하지 않았습니다.
